# The Aero Forge – React + Node

## Run locally (two terminals)

```
cd server && npm install && cp .env.example .env   # fill in JWT_SECRET, ADMIN_PASSWORD, ADMIN_EMAIL (or leave NODE_ENV out for local dev)
npm start                                          # :5001
cd client && npm install && npm run dev            # http://localhost:5173
```

Admin: <http://localhost:5173/#/admin>

In local development you can skip `.env`: the server makes up a one-off admin password and prints it.
In production (`NODE_ENV=production`, or a built `client/dist` next to the server) it **refuses to start**
without a strong `JWT_SECRET`, `ADMIN_PASSWORD` and an `ADMIN_EMAIL`.

## Production

```
cd client && npm run build && cd ../server && npm start
```

Serves the site and the API from one port. Set the variables from `server/.env.example`, especially `SITE_URL`.
Keep `server/data.json` and `server/uploads/` on a persistent disk and back them up. They are git-ignored on purpose
(inquiries contain customers' personal details); a fresh install starts from `server/data.seed.json`.

- HTTPS: the server redirects http to https when the host's proxy reports `x-forwarded-proto: http`, and sends HSTS.
  Also switch on "Force HTTPS" in your hosting panel.
- Analytics: set `VITE_GA_ID` in `client/.env` before building. Nothing loads until a visitor accepts the cookie banner.
- SEO: `/robots.txt` and `/sitemap.xml` are generated by the server. Page titles/descriptions live in
  `server/seo.js` and `client/src/seo.js` (keep them in sync).

## How it works

- STEP files are measured in the visitor's browser (OpenCascade WASM) – nothing is uploaded until they send an inquiry.
- Price = shell + infill volume (wall thickness, infill %, supports) -> weight x material price + print time x machine rate -> markup -> x qty + setup fee.
- All text, services, FAQs, materials and every price number are editable in Admin; inquiries (with attached files) appear there too.
